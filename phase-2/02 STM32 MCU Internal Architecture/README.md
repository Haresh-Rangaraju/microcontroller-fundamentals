
# Block 2 — STM32 MCU Internal Architecture

## Objective

Understand how the CPU, memory, bus system, peripherals, clock system, and GPIO interact inside an STM32 microcontroller to execute firmware and control hardware.

## 1. Overview of STM32 Architecture

An STM32 microcontroller typically contains:

- **CPU:** Executes program instructions.
- **Flash memory:** Stores firmware and persistent constants.
- **SRAM:** Stores runtime data such as variables, stack contents, and buffers.
- **Bus system:** Transfers accesses between the CPU, memory, and peripherals.
- **Peripherals:** Provide hardware functions such as GPIO, timers, ADC, UART, SPI, and I2C.
- **Clock system:** Supplies timing signals to the CPU and peripherals.
- **Reset and interrupt mechanisms:** Support system startup and hardware event handling.

The exact architecture and available peripherals depend on the STM32 model.

## 2. CPU and Cortex-M Processor

The CPU executes machine instructions generated by the compiler from the firmware source code.

Important processor registers include:

| Register | Purpose |
|---|---|
| R0–R12 | General-purpose registers |
| SP | Stack Pointer |
| LR | Link Register |
| PC | Program Counter |

The CPU performs instruction execution and processing. Dedicated peripherals perform specialized hardware operations.

## 3. Flash Memory and SRAM

| Feature | Flash | SRAM |
|---|---|---|
| Purpose | Program code and persistent constants | Runtime data |
| Retains contents without power | Yes, normally | No |
| Typical contents | Firmware instructions | Variables, stack, buffers |

The compiler, linker, startup code, and optimization settings determine the actual placement and initialization of program data.

## 4. Bus System

The bus system connects the CPU, memory, and peripherals.

A bus transaction conceptually involves:

- **Address:** Identifies the location being accessed.
- **Data:** Carries the value being read or written.
- **Control information:** Indicates the type of transaction.

When the CPU accesses a peripheral register, the interconnect routes the access to the appropriate hardware component.

The bus system enables communication between components; it is not itself the peripheral.

## 5. Memory-Mapped Peripherals

STM32 peripherals generally expose registers at specific addresses in the processor's address space.

Firmware accesses these registers to configure peripherals, read status, and control hardware.

Common GPIO registers include:

| Register | Purpose |
|---|---|
| MODER | Configures pin mode |
| OTYPER | Configures output type |
| OSPEEDR | Configures output speed characteristics |
| PUPDR | Configures pull-up/pull-down settings |
| IDR | Reads input-pin states |
| ODR | Holds output-data values |
| BSRR | Sets or resets output bits through dedicated write operations |

Register availability and behavior depend on the STM32 model.

For many STM32 GPIO implementations using MODER, each pin has a two-bit mode field:

| Field value | Mode |
|---|---|
| 00 | Input |
| 01 | General-purpose output |
| 10 | Alternate function |
| 11 | Analog |

Always verify the selected device's reference manual.

## 6. Clock System

The clock system supplies timing signals required by the CPU and peripherals.

Many STM32 devices use the Reset and Clock Control (RCC) system to manage clock configuration and peripheral clock enables.

Enabling a peripheral clock and configuring that peripheral are separate tasks.

Incorrect clock configuration can prevent expected peripheral operation or produce incorrect timing.

## 7. Reset and Interrupts

**Reset:** Establishes the processor's startup conditions.

**Interrupts:** Allow the processor to respond to events generated by peripherals or other interrupt sources.

On Cortex-M devices, the Nested Vectored Interrupt Controller (NVIC) manages processor interrupt handling, including interrupt enabling and prioritization.

The exact interrupt sources and configuration depend on the STM32 model.

## 8. Firmware-to-Hardware Interaction

Consider controlling an LED through a GPIO pin.

1. Enable the required GPIO peripheral clock.
2. Configure the pin's mode.
3. Set the desired output state through the appropriate GPIO register.
4. The GPIO hardware applies the output state to the physical pin.
5. The external circuit responds to the resulting electrical signal.

The CPU does not directly drive the external circuit through software instructions. It configures and controls dedicated GPIO hardware.

## 9. Illustrative Embedded C Example

The following example demonstrates the concept of setting a GPIO output bit. It is illustrative and assumes that the GPIO clock and pin mode have already been configured correctly.

```c
GPIOA->ODR |= (1U << 5);
```

Explanation:

- `GPIOA` identifies GPIO port A.
- `ODR` is the output data register.
- `(1U << 5)` creates a mask for bit 5.
- `|=` sets bit 5 while preserving the other bits in the value read.

This statement requests a logic-high output state for the corresponding pin when the GPIO is configured appropriately.

The exact pin mapping and hardware behavior depend on the STM32 model and board.

This read-modify-write operation is illustrative; it is not guaranteed to be atomic. Where appropriate, an STM32 GPIO `BSRR` write can set or reset selected output bits without a read-modify-write sequence.

## 10. Engineering Considerations

- A peripheral may require its clock to be enabled before use.
- A register write alone does not guarantee the intended hardware behavior.
- Pin mode and output state are separate configuration concerns.
- Flash and SRAM have different purposes.
- Peripherals can perform many operations without continuous CPU involvement.
- Incorrect clock or pin configuration can cause unexpected behavior.
- Register definitions and clock requirements must be checked against the selected STM32 reference manual.

## 11. Key Takeaways

1. The CPU executes instructions.
2. Flash stores firmware; SRAM stores runtime data.
3. The bus system transfers accesses between components.
4. Memory-mapped registers provide software access to peripheral hardware.
5. The clock system supports CPU and peripheral operation.
6. GPIO connects internal peripheral behavior to physical pins.
7. Reset and interrupts support startup and event handling.
8. Correct hardware configuration is essential for expected firmware behavior.

## Scope

This block covers STM32 MCU internal architecture only. It does not attempt to teach detailed peripheral programming, advanced interrupt handling, or other future learning blocks.
